# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Happy Gadgets — a single-page marketing/catalog site for a gadget shop (New Pioneer Mall PA85). There's no
cart or checkout: every product/category CTA deep-links to a pre-filled WhatsApp chat (`wa()` helper in
`src/routes/index.tsx`) or a `tel:`/`mailto:` link. Almost all content currently lives in one file,
`src/routes/index.tsx` (categories, featured products, contact info, and every page section as a component).

Deploys to **Vercel** — `vite.config.ts` builds with nitro's `vercel` preset, which produces Vercel's Build
Output API v3 format (`.vercel/output/`) directly from `npm run build`. No project-specific Vercel config is
needed beyond that.

## Commands

Package manager is **bun** (see `bun.lock`, `bunfig.toml`), though scripts also work with npm. Run
`bun install` after any `package.json` change to keep `bun.lock` in sync — it won't self-update from npm.

```sh
bun install         # install deps
bun run dev          # vite dev server
bun run build        # production build (vite build)
bun run build:dev    # development-mode build
bun run preview      # preview a production build
bun run lint         # eslint .
bun run format       # prettier --write .
```

There is no test suite configured in this repo.

`bunfig.toml` enforces a 24h supply-chain guard (`minimumReleaseAge`): newly published package versions are
rejected by `bun install` unless the package is in `minimumReleaseAgeExcludes`. Adding a package to that
exclude list bypasses the guard — confirm with the user before doing so.

## Architecture

**Stack**: TanStack Start (file-based SSR router) + React 19 + TypeScript + Tailwind CSS v4 + shadcn/ui
(new-york style, Radix primitives) on Vite, building with nitro against the `vercel` preset.

**Routing** (`src/routes/`): file-based via TanStack Router — see `src/routes/README.md` for the naming
conventions (`$id` dynamic segments, `{-$cat}` optional, `$` splat, `_layout` layouts). `__root.tsx` is the
one app shell (renders `<Outlet />`, global `<head>` meta/fonts, not-found/error boundaries) — never create
`src/pages/` or Next/Remix-style route files. `src/routeTree.gen.ts` is auto-generated by the TanStack router
plugin; never hand-edit it.

**Vite config** (`vite.config.ts`): plain, hand-written config — `tsConfigPaths`, `@tailwindcss/vite`,
`tanstackStart` (from `@tanstack/react-start/plugin/vite`), and `viteReact`. The `nitro/vite` plugin (preset
`"vercel"`) is only added when `command === "build"`, so `vite dev` keeps its own dev-server path and never
runs nitro. The `tanstackStart.server.entry` option points SSR at `src/server.ts` instead of the framework
default — this only rewires which module handles the request, not the deploy target, so it works unchanged
regardless of nitro preset.

**SSR error handling** — three files work together to guarantee a real error page is shown instead of a raw
JSON 500, since h3 (nitro's HTTP layer) swallows in-handler throws into an opaque
`{"unhandled":true,"message":"HTTPError"}` response:
- `src/start.ts` — server middleware (`createMiddleware().server`) that catches thrown errors before h3 does.
- `src/lib/error-capture.ts` — wraps `console.error` and window error/unhandledrejection listeners to record
  the last real Error (with stack/cause chain) out-of-band, in case h3 swallows it anyway.
- `src/server.ts` — the SSR entry (`fetch(request, env, ctx)`, TanStack Start's own generic handler shape,
  not platform-specific); detects an h3-swallowed 500, recovers the captured error, and renders
  `src/lib/error-page.ts`'s static HTML instead of the raw JSON body.

Changes to error handling should preserve this chain (middleware → capture → server fetch wrapper) rather
than adding ad hoc try/catch at a single layer.

**Styling** (`src/styles.css`): Tailwind v4 CSS-first config (`@theme inline`, `@utility`) — there is no
`tailwind.config.js`. Design tokens are OKLCH CSS custom properties on `:root` (`--primary`, `--accent`,
`--border`, etc., plus a `--whatsapp` brand color for WhatsApp CTAs) mapped into Tailwind's color scale via
`@theme inline`. Custom utilities beyond Tailwind's defaults are declared here too: `bg-gradient-hero`,
`bg-gradient-brand`, `bg-gradient-soft`, `text-gradient-brand`, `shadow-glow`, `shadow-card`. Two font
families are wired up: `font-display` (Space Grotesk, headings) and `font-sans` (Inter, body), loaded via
Google Fonts `<link>` tags in `__root.tsx`, not `next/font` or self-hosting.

**Components** (`src/components/ui/`): shadcn/ui-generated primitives (see `components.json` for the
generator config: new-york style, Lucide icons, `@/components`, `@/lib`, `@/hooks` aliases). Treat these as
generated/vendored — prefer regenerating or composing over hand-editing internals, and use `cn()`
(`src/lib/utils.ts`, `clsx` + `tailwind-merge`) for conditional class merging, matching existing usage.

**Path alias**: `@/*` → `./src/*` (defined in `tsconfig.json`, mirrored in `components.json` aliases).

## Linting & formatting

- ESLint (`eslint.config.js`) runs Prettier as a lint rule (`eslint-plugin-prettier/recommended`), so
  `bun run lint` also enforces formatting — don't hand-format against Prettier's config in `.prettierrc`
  (100 print width, double quotes, trailing commas everywhere).
- `@typescript-eslint/no-unused-vars` is deliberately **off** and `noUnusedLocals`/`noUnusedParameters` are
  off in `tsconfig.json` — don't add unused-var lint fixes that aren't otherwise needed.
- A custom `no-restricted-imports` rule blocks importing Next.js's `server-only` package; server-only modules
  should be named `*.server.ts` or use `@tanstack/react-start/server-only` instead.
